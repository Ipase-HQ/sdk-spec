# Changelog

Every change to the contract (schema, protocol, fixtures) gets a line here, and every schema or protocol change also bumps VERSION. The format follows Keep a Changelog. The version headings are the values VERSION has held.

## [Unreleased]

## [1.0.0-draft.2] - 2026-10-27

### Added

- Root package with npm run validate: compiles schema/batch.schema.json with ajv under draft 2020-12 strict mode, checks every file in examples/valid validates and every file in examples/invalid is rejected, and checks VERSION against the fixtures.
- examples/: valid batches (one per SDK, lifecycle names, resume after timeout, server events with and without a client session, the minimal batch, the property limits) and one invalid batch per rule, generated by scripts/generate-examples.mjs.
- mock-server/: the TypeScript ingest double. Validates POST /v1/batch against the schema, records every request, replays scripted responses, exposes POST /__scenario, GET and DELETE /__recorded and GET /__health. node:test suite and a Dockerfile.
- GitHub Actions workflow: validate, mock-server tests, Docker image build with a smoke test, push to GHCR on main.
- Schema: reserved name `$tap` for auto-captured taps and clicks (element required, with id or label) and `$events_dropped` as a track event carrying properties.count. The reserved list is closed: `$app_installed`, `$app_updated`, `$app_backgrounded`, `$app_foregrounded`, `$tap`, `$events_dropped`. Any other name starting with `$` is invalid.
- Schema: context.platform (android, ios, web, desktop, server) is required; context.browser (name, version) is optional and sent by the js SDK; context.sdk.spec is required and must be a semver string; app.bundle_id is required on every platform except server.
- fixtures/: one executable file per scenario (offline-then-online, process-kill, backoff-429, session-timeout, identity-stitching, privacy, property-limits) with the steps a harness drives and the exact events the mock server must observe, matched with $repeat, $platforms, $session, $label and $same_timestamp_as, plus checks, request bounds, forbidden strings and local rejections. fixtures/scenario.schema.json describes the format and npm run validate checks every file against it.
- Mock server: reserved_name comes from the schema; the test suite loads every fixture through POST /__scenario.
- protocol.md rewritten so an SDK author can implement a client from it alone: keys and headers, response and rejection codes, exact backoff and in-flight rules, the per-type field matrix, the reserved names and their order, context sources per platform, the session state machine (launch, background, foreground, timeout, kill recovery, reset), screens and dwell with the denylist rule, identity and server-side forwarding, queue and flush, consent, auto-capture per platform, local validation, clock skew, the public API and conformance.
- Decisions that go beyond the development plan are recorded in ../docs/adr: 0001 reserved names ($tap, $events_dropped), 0002 launch types, 0003 server-side events, 0004 context.platform and context.browser, 0005 web transport without sendBeacon.

### Changed

- fixtures/scenarios.json is gone; its seven scenarios became the files above. The mock server still accepts a whole fixture object on POST /__scenario.
- Schema: event_id must be a lowercase UUIDv7 (pattern, not just format uuid). device_id and session_id must be lowercase UUIDs; the nil UUID is the session id of a server-side event with no client session.
- Schema: each event type now has an exact field set. Fields that belong to another type are rejected (a track with launch_type, a screen with name, traits outside identify). session_end requires duration_ms, screens_viewed and events_count. screen_exit requires screen.duration_ms and may not carry previous or properties. screen events may not carry screen.duration_ms, and screen.previous and screen.previous_duration_ms come together.
- Schema: seq, duration_ms, screens_viewed and events_count are capped at 4294967295 so they fit the ClickHouse UInt32 columns. context.device.screen must be width x height.
- Schema: launch_type meanings fixed: cold (process start or page load with no live session), warm (new session while in the foreground, which is what reset() emits), resume (foreground after the session timeout).

## [1.0.0-draft.1] - 2026-10-27

### Added

- schema/batch.schema.json: first draft of the batch envelope and the six event types (screen, screen_exit, track, identify, session_start, session_end) with context, element, screen and flat property maps.
- protocol.md: endpoint, headers, limits, response table, retry rules, envelope rules, sessions, screens, identity, queue and flush, privacy.
- fixtures/scenarios.json: seven conformance scenarios (offline then online, process kill, backoff on 429, session timeout, identity stitching, privacy, property limits).
