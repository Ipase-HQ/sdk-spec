# sdk-spec

The contract between every SDK and the ingest service of the User Monitoring Platform. Nothing in here runs in production; it is what the SDKs and the ingest service are tested against.

- schema/batch.schema.json: JSON Schema (draft 2020-12) for the batch body and the event envelope. The source of truth.
- protocol.md: the wire protocol in words (endpoint, headers, limits, responses, retries, sessions, identity, clock skew).
- fixtures/: conformance scenarios every SDK must pass against the mock server, one executable JSON file per scenario plus the schema that describes them. fixtures/README.md says how a harness runs one.
- examples/: payloads that validate against the schema and payloads that must not. Generated by scripts/generate-examples.mjs.
- mock-server/: a small TypeScript ingest double that validates, records, replays scripted responses and judges a fixture run through POST /__verify. Ships as a Docker image from CI.
- VERSION: the spec version. Bump it with every schema or protocol change and add a line to CHANGELOG.md; SDKs report it in context.sdk.spec.

See ../docs/development-plan.md sections 4 and 8 for the reasoning behind every rule.

## Commands

- npm install, then npm run validate: the schema compiles, examples/valid pass, examples/invalid fail, every fixture matches fixtures/scenario.schema.json and VERSION.
- npm run examples: regenerate examples/ from scripts/generate-examples.mjs.
- cd mock-server && npm install && npm test: type-check and run the mock server's tests.
- cd mock-server && npm run dev: run the mock server on http://localhost:8787.
- docker build -f mock-server/Dockerfile -t sdk-spec-mock-server . from this folder builds the image CI publishes.
